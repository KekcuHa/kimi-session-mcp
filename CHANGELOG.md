# Журнал изменений

## [0.0.5] — 2026-11-15
- Автодискавери адреса локального API: порт у desktop-приложения динамический, поэтому при незаданном `KIMI_SESSION_MCP_BASE_URL` адрес берётся из `~/.kimi-code/server/instances/*.json` (файл с самым свежим `heartbeat_at`); результат кешируется на 30 с и сбрасывается при недоступности API. Дефолт `http://127.0.0.1:58627` остаётся последним фолбэком.
- Обновлена задеплоенная копия `~/.local/share/kimi-session-mcp` (отставала: не было `ManageSession` из 0.0.4).

## [0.0.4] — 2026-11-14
- Публикация на GitHub: лицензия MIT, метаданные package.json, двуязычный README и исключение локального `.kimi-code/` из репозитория.
- Объединены публичная история и локальная история с `ManageSession`; исполняемый режим `src/index.js` восстановлен.
- `kimi-sessions` снова выбран основным каналом для живых локальных вкладок Kimi; задокументирована несовместимость отдельных AgentMBX identity с общим MCP-процессом Kimi web 2.6.1.

## [0.0.3] — 2026-11-14
- Добавлен инструмент `ManageSession`: действия жизненного цикла сеанса (`archive`, `restore`, `reload`, `takeover`, `delete`) через colon-эндпоинты Server API `POST /api/v1/sessions/{id}:{action}`.
- `delete` требует явного `confirm: true`; неизвестное действие отклоняется с перечнем допустимых.
- Рецепт проверен curl'ом на боевом сервере 2.6.1: `/archive` через слэш даёт 404, правильная форма — `{id}:archive`.

## [0.0.2] — 2026-11-14
- Проведена повторная сквозная проверка MCP и сравнение с AgentMBX.
- Основным механизмом обмена выбран AgentMBX; автоматическая загрузка `kimi-sessions` в проекте отключена.
- Код сохранён как резервный вариант с возможностью ручного подключения.

## [0.0.1] — 2026-11-05
- Добавлен MCP-сервер для обнаружения сеансов Kimi Code и обмена текстовыми сообщениями через локальный REST API.
- Добавлены доставка в активный ход через `prompts:steer` и чтение ответов через `GetMessages`.
- Проведена сквозная проверка обмена между двумя реальными сеансами Kimi Code 2.4.1.
